El matrimonio perfecto: fpdart y Signals

Mito común: "fpdart es solo para Riverpod".

Realidad: fpdart es una librería de Programación Funcional pura. No sabe absolutamente nada sobre el UI, Flutter o el manejo de estado. Su único trabajo es controlar el flujo de datos y los errores matemáticamente.

Separación de Responsabilidades

Para entender por qué se complementan tan bien, hay que ver qué hace cada uno:

  • fpdart (Capa de Dominio/Datos): Atrapa las excepciones feas y las convierte en valores seguros. En lugar de hacer un try/catch que pueda explotar la app, usas Either<Error, Exito>.
  • Signals (Capa de Presentación): Toma los valores seguros y los muestra reactivamente en la pantalla.

¿Cómo se ven trabajando juntos?

Imagina un Caso de Uso que busca destinos. Con fpdart, el caso de uso garantiza que nunca lanzará una excepción; siempre devolverá una respuesta controlada (Izquierda = Error, Derecha = Lista de Destinos):

// 1. Dominio (fpdart)
Future<Either<Failure, List<SavedDestination>>> getDestinations() async {
  try {
    final data = repository.getAll();
    return Right(data); // Todo salió bien
  } catch (e) {
    return Left(DatabaseFailure('Error leyendo Hive')); // Hubo un error controlado
  }
}

Ahora, en tu Controlador (ViewModel), Signals reacciona a este resultado de forma ultra-limpia sin ensuciar la UI con bloques try/catch:

// 2. Presentación (Signals + fpdart)
class DestinationController {
  final state = signal<AsyncState<List<SavedDestination>>>(AsyncLoading());

  Future<void> load() async {
    final result = await getDestinationsUseCase();
    
    // fpdart nos regala el método .fold() para manejar ambos casos obligatoriamente
    result.fold(
      (failure) => state.value = AsyncError(failure.message),
      (data) => state.value = AsyncData(data),
    );
  }
}
¿Por qué le sacamos buen provecho?

Porque Signals es extremadamente simple y reactivo, pero no tiene un sistema robusto de tipado de errores nativo. fpdart suple esa carencia. fpdart obliga al programador (en tiempo de compilación) a manejar tanto el caso de éxito como el de error antes de actualizar el Signal. Es arquitectura a prueba de balas.
